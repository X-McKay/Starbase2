# ADR 0011: Bounded repository SDLC pilot

Status: accepted

Date: 2026-09-28. Owner: Core/runtime. Al explicitly authorized the recommended
autonomous SDLC path and designated `X-McKay/algent` as the disposable pilot.
That covers pilot branches, PR submission, tests and published review; merging
remains a Commander decision. Other repositories remain observation-only.

## Decision

Extend existing Core and Temporal with V7, preserving older histories. Core owns
standing policy, exact repository/revision/build, opportunity deduplication,
state, independent behavioral grading, cancellation and publication claims.
Trusted Python adapters own fixed-origin GitHub effects and disposable microVM
execution. Separate Qwen lead, implementer and reviewer calls coordinate through
retained evidence. Godot projects the same records without dispatch on travel.

Start with one real opportunity family: algent's SQLite conversation-history
ordering. A trusted source rule admits candidates; models can decline or request
revision. This bounded family is not arbitrary-repository repair qualification.
The source, candidate and tests are immutable artifacts. Seven behavior outputs
are independently compared by Core; agent-written claims cannot grant success.
The pilot adds public regression tests and a scoped Python 3.13.5 CI workflow.

Keep the established microsandbox 0.6.14 boundary, with an exact Python 3.13.5
image matching algent's declared runtime. Candidate code receives no host mounts,
network or provider credentials. It cannot edit the Core oracle, publisher or
policy. Passing this persistence slice does not certify Redis/API/application
integration, all security properties or general SDLC competence.

Publication uses stable branch and commit identities, fresh base/policy checks,
and durable one-shot intent for mutable GitHub effects. Unknown PR/review effects
are reconciled by reading GitHub before any subsequent decision, never blindly
repeated. Publication and CI state remain distinct from verified merge/useful
deployment. No XP or capability promotion follows merely from opening a PR.

## Identity and alternatives

A dedicated GitHub App remains the intended operational identity. The initial
authorized local pilot can use the existing private CLI credential behind the
strict algent-only adapter; its underlying OAuth scope is broader than adapter
authority. No credential enters model context, source artifacts or the VM.
Provisioning an App requires owner-account setup and is not fabricated locally.

A manual assistant-authored PR would not test autonomous coordination. A generic
shell agent with publishing credentials would collapse the trust boundary. A new
swarm service would duplicate Core/Temporal ownership without solving either
problem. The chosen smaller extension reuses durable execution and isolation.

## Acceptance and review

Require real baseline failure, Qwen-authored scoped patch, independent candidate
pass, specialist review, one reconciled PR, retained CI observation and a usable
native view. Test policy revocation, malformed evidence, duplicate dispatch,
uncertain publication, cancellation and restart. Preserve failed attempts.

Review before adding repository families, dependency installation/networking,
automatic merge, unbounded operation, persistent learning or new identities.
The schema migration requires a backup and compatible binary; it does not
authorize Kubernetes deployment or relaxing existing repository policies.
